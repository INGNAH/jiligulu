# 星灯火锅店

使用 Godot 4.6.3 打开 `hotpot/project.godot`，按 F5 试玩，或运行 `godot --path hotpot`。

## 经营一晚

1. 在市场买食材，去料理台研发菜谱、装盘备菜。在营业铃选择今晚供应的主菜、自取菜和特别菜单。
2. 开门前可以分别雇点单员、送餐员和补餐员：每人招聘费 30 金、每晚工资 8 金。各岗位可指定优先分区，经验独立累计。没雇人的岗位由后厨兼顾，速度较慢；店长可在桌边点单、到厨房端主菜或取盘补餐。顾客自行取用素菜、蘸料、饮品和冰淇淋。
3. 从客人或气泡接下定制单，到厨房点击对应厨具。可以按原方制作，也可以加料满足客人的喜好和本餐要求。
4. 补餐员从厨房取盘，沿通道走到自取台，优先处理缺菜和客人等待的区域。点击食材台查看各盘剩余份数。每盘满装六份，四至五份显示“大量”，一至三份显示“少量”，取完显示“空”。
5. 打烊时查看各桌等待、评价与收支。三个存档位各自保存经营进度。

WASD 或方向键移动，E 交互，Esc 关闭面板，P 暂停。准备期按 B 装修，可以摆放桌椅、分区、移动厨房和食材台，添加墙面与员工通道，再检查布局能否开门。

## 烹饪与保存

清炖霜牛需要牛肉和豆腐各1份，在火候条40—70出锅，成功产出2盘并增加熟练度。失误改成普通牛肉盘；成功3次后解锁快捷制作。目前只做了一种烹饪小游戏，委托烹饪与更多菜谱后续扩展。

主菜单提供三个独立存档位、新游戏与继续游戏，覆盖已有存档需确认。准备期在手册或暂停菜单保存，开门前和日终自动保存。存档包含布局、房型、分区、员工岗位、资金、食材、熟练度和好感。兼容v0.1存档，旧档自动使用默认双区布局。营业过程暂不保存；营业中退出后恢复开门前的检查点。退出会提示确认。每个存档保留上一份有效备份，主文件损坏时尝试恢复，写入失败会明确提示。

Windows存档通常位于 `%APPDATA%/Godot/app_userdata/星灯火锅店 · Demo/saves/slot_1.json`（另有slot_2、slot_3与各自.bak备份）。旧版 `starpot.json` 可从主菜单导入空位，原文件保留。设置单独保存在 `settings.cfg`。字体Noto Sans CJK许可证见 `hotpot/assets/FONT-LICENSE.txt`。

## 验证与导出

```sh
godot --headless --path hotpot --editor --import --quit
XDG_DATA_HOME=/tmp/starpot-economy godot --headless --path hotpot --script res://tests/smoke.gd
XDG_DATA_HOME=/tmp/starpot-layout godot --headless --path hotpot --script res://tests/layout.gd
godot --headless --path hotpot --export-release "Windows Desktop"
godot --headless --path hotpot --export-release Linux
```

在独立用户数据目录运行测试，避免测试覆盖试玩存档。布局测试覆盖分区、碰撞、通道、运输、补餐容量、员工行走、等待评价、连续三天、结算存档和旧存档迁移。`tests/visual.gd` 是 Linux 显示环境中的原生画面及 B/R 输入检查，截图输出到构建目录。

Windows导出需匹配的官方模板。Windows导出和Linux原生运行分别验证，尚未在Windows实机验证。没有自动发布、提交或推送操作。

## 美术接入基础（v0.2.2）

已建立SpriteSpec、ArtPack和绘制适配器，支持静态PNG、逐帧动画、源图锚点、缩放与偏移，以及明确的桌椅方向、角色动作和高清立绘槽位。默认包为空，维持程序占位图。素材缺失按对象回退，视觉替换不改变碰撞与经营数据。

代码侧接入说明：`docs/art/程序接入说明.md`。用户只需交付设计素材，无需填写Godot资源配置。当前已接桌椅、自取台、厨房/采购入口、餐盘食物、锅具、角色、餐厅地板和露米管理立绘；其他UI和场景装饰等待实际素材后继续接入。

新增资源测试：`XDG_DATA_HOME=/tmp/starpot-art-test godot --headless --path hotpot --script res://tests/art.gd`。原生渲染检查见`tests/art_visual.gd`，其中色块是测试纹理，不是游戏美术。

## v0.3 新增经营与基础流程

- 开店管理中切换18、24、30金餐费；高价降低客流并提高评价要求，入座客人收统一基础餐费。
- 料理台支持一键批量装盘，消耗全部基础原料，每份制作2盘；需要研发炖菜时请先留原料。
- 露米每趟成功补餐获得1经验，完成营业额外2经验；30/60经验升至二/三级，步速提升，三级多携带1盘。每日工资仍为8金。
- 日终报表增加各菜品销量、当前餐费、总食用盘数与员工补餐次数和经验。
- 暂停菜单支持继续、保存、设置、返回主菜单和退出；设置包括全屏、切换窗口自动暂停与总音量。当前尚未制作音乐音效。
- UI和场景仍使用占位美术，资源接入接口保留，可在用户设计完成后替换。

新增验证：`XDG_DATA_HOME=/tmp/starpot-session-test godot --headless --path hotpot --script res://tests/session.gd`。本轮43项会话与经营检查，连同已有18项经营、35项布局、19项美术接口检查，共115项通过。`tests/app_visual.gd` 验证原生窗口下新游戏、暂停、设置、结算、返回主菜单及继续的鼠标和键盘流程。

## v0.3.1 营业准备

市场、料理台和开店铃新增库存与备菜计划。按当前餐费预计客流，每客3盘计算总量，已有炖菜与基础成品均计入；六种基础菜按库存均衡补齐。清单扣除现有原料，再按每组3份计算购买数量及费用。可以按清单采购、按计划装盘，多余原料保留。资金不足不会部分采购，重复操作不会超额购买。

开店检查显示现有与建议餐盘数量，以及人手和工资提醒。12盘仍是开门下限，建议数量只作经营参考，不保证口味满足或配送及时。采购和装盘仅在准备期可执行。新增15项检查通过，连同此前115项共130项。

## v0.3.2 跨天营业记录

店长手册与日终结算新增经营记录入口，保留最近30个营业日。可以查看最近7次营业的收入、支出、净收益、客流、销量和按客人数加权的评价，并比较最近两次营业的收入、净收益与客流变化。每天的明细包括当日餐费、桌数、食材台数、菜品销量和分区评价及缺餐等待时间。

记录随三个存档位分别保存；旧档兼容，未记录的历史不会补造。支出按实际付款日计入，包含采购、招聘、装修和工资，不代表已售食材成本。新增18项检查，连同原有130项共148项通过。
