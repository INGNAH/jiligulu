# 美术资源接入（代码侧）

已实现资源配置接口，默认资源包为空，游戏显示现有占位画面。设计师无需编辑这些代码或填写Godot配置，交PNG与说明后由程序侧处理。

## 资源结构

- `hotpot/art/sprite_spec.gd`：单个图像/动画资源，包含有序Texture2D帧、原图锚点、显示缩放、偏移、FPS、循环与立绘采样。
- `hotpot/art/blank_sprite.tres`：空模板，可在Godot Inspector里复制并指定PNG；没有帧时不会用于绘制。
- `hotpot/art/art_pack.gd`、`default_pack.tres`：槽位名到图像资源的映射。主场景的`art_pack`导出属性可指定整套资源包。引用PNG用Godot资源引用，导出时随包携带，不依赖工作区绝对路径。
- `hotpot/rendering/art_renderer.gd`：验证与缓存有效资源、逐帧播放、缺失回退、演员动画时钟、高清立绘控件。
- `main.gd`：根据家具方向、餐带连通、角色状态选择槽位；保持原有逻辑坐标和前后排序。

资源无效或尚未提供时仅回退对应对象，不影响其他已接入图像；不每帧重复加载磁盘文件。主场景启动时输出无效条目的诊断。

## 已接通的槽位

| 槽位 | 世界位置/用途 |
|---|---|
| `environment/floor` | 每个可用餐厅格子的中心；建议配置后的图像正好覆盖40×40逻辑单位 |
| `furniture/table/0` … `/3` | 桌子占地中心；方向与布局rot一致 |
| `furniture/chair/0` … `/3` | 每把椅子的占地中心；方向与所属桌子rot一致 |
| `belt/ns`, `belt/ew` | 竖、横餐带 |
| `belt/ne`, `belt/es`, `belt/sw`, `belt/nw` | 连接的两方向，以n/e/s/w固定顺序命名 |
| `furniture/feeder` | 补餐点格子中心；“补”字分区色标由代码绘制 |
| `furniture/kitchen` | 料理台地面基准(190,630) |
| `furniture/market` | 采购入口地面基准(170,255) |
| `prop/hotpot` | 桌上每份锅的中心；目前相对对应格子向上29逻辑单位 |
| `prop/plate` | 餐盘中心，沿餐带移动；目前向上24逻辑单位 |
| `food/0` … `/6` | 餐盘上的食物层；蘑菇/牛肉/虾/火椒/豆腐/萝卜/炖牛 |
| `character/player/{state}` | 掌柜脚底逻辑位置 |
| `character/lumi/{state}` | 露米脚底逻辑位置 |
| `character/hero/sit`, `/idle` | 特殊客人莱恩 |
| `character/guest_0/sit` … `guest_2/sit` | 三种普通顾客；没有sit时可回退对应idle |
| `portrait/lumi/neutral` | 营业管理/招聘面板的立绘位置，保持宽高比 |

角色state：`idle`、`walk`、`carry_idle`、`carry_walk`。端盘动作缺失时退到相应空手动作，最后退到idle，再退到程序小人。不要求每次交齐全部动作。切换动作会重启动画，同一动作继续播放；普通客人目前是原地坐姿，不伪造尚未实现的入座行走。

桌椅必须明确指定方向资源。不将2.5D图像平面旋转代替不同视图。可以让多个槽位引用同一资源，但须美术确认对称性。目前桌椅仍属于双人桌套件，资源拆分不代表已做独立椅子布局功能。

## 锚点与采样

锚点单位为源图像素，左上角为(0,0)，人物通常是脚底，桌椅是地面占地中心。目标左上角=世界位置+offset-anchor×display_scale。

场景主画布采用nearest采样，像素素材建议整数倍缩放；角色和家具按现有地面Y坐标排序，改变图片透明边距/高度不会改变碰撞或座位。图像按整件排序，尚未提供任意前后层分离接口；拱门等复杂素材收到后再增加。

UI立绘使用独立TextureRect，pixel_art=false时使用线性采样，保持宽高比；管理面板支持滚动，避免立绘加入后挤掉操作按钮。世界场景的SpriteSpec.pixel_art不会逐对象切换采样，当前世界画布统一nearest。

台面高度、餐盘高度仍使用当前逻辑基准，素材接入时可以通过offset对齐；如设计改变高度，程序侧同步调整锅与餐盘挂点。墙面、灯具、盆栽和完整UI皮肤尚未转换为美术槽位，不在这次已完成范围内。

## 程序接图步骤

1. 将设计师PNG放在`hotpot/art/imported/`的对应批次目录（首批交付时创建）。
2. Godot导入后为每个视图创建SpriteSpec资源，填frames、anchor、display_scale、offset。动画所有帧尺寸需一致。
3. 将资源填入default_pack.tres的sprites字典对应槽位，或创建新资源包供主场景引用。
4. 运行资源验证与经营回归；检查人物与桌面遮挡、餐带接缝、方向、行走动画、立绘布局和缩放。
5. 用实际PNG资源做一次导出包运行验证，随后给设计师截图和试玩包确认。

验证命令（使用隔离存档目录）：

```
XDG_DATA_HOME=/tmp/art-tests godot --headless --path hotpot --script res://tests/art.gd
XDG_DATA_HOME=/tmp/layout-tests godot --headless --path hotpot --script res://tests/layout.gd
XDG_DATA_HOME=/tmp/economy-tests godot --headless --path hotpot --script res://tests/smoke.gd
```

没有用户正式素材时使用测试内存纹理验证接入，不把测试色块当作正式美术。
