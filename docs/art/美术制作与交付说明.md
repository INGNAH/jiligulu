# 星灯回转锅：餐厅阶段美术制作与交付

版本：2026-11-17。美术负责人：用户；代码、游戏构建与素材接入：Codex。

本清单基于当前 Godot 餐厅原型。清单描述要制作的资源，不代表已经接入了图片资源系统。当前家具、人物仍主要由代码绘制；拿到首批素材后，会改为图片/动画资源，并适配遮挡、碰撞和点击区域。

## 已定稿的视觉基准（2026-11-19）

唯一母图是本次对话中用户确认的餐桌角落：左侧栗发店长，右侧紫发客人坐在桌后，中央铜锅冒白汽，右侧青绿色餐带，蓝墙拱窗里可见浮岛。人物、背景、道具、界面插画和灯光都对照这一张图。旧试玩截图和早期单件素材仅用于记录开发过程。

- **人物比例**　按母图里店长的头顶、下巴、鞋底取样。头发计入头高，身体连鞋明显短于头部。店员、客人沿用这一比例；坐下时以桌沿遮住身体，保留脸和端盘的小手。
- **场景比例**　以站立店长的可见全高为尺，同时对照锅口宽度、桌沿厚度、座位高度、窗台和墙地交界线。保留母图中人物相对背景的画面占比。扩大营业区域时延伸或滚动场景，避免为了塞进全店而缩小人物。
- **镜头与遮挡**　固定斜俯视，使用分层像素画。家具同时看得见顶面和正面；餐带有青绿侧板、浅色包边、木脚和接地阴影。墙、地面、窗户按原纵横比排布。
- **色彩与笔触**　直接从母图取墙面蓝灰、木面蜜色、围裙和餐带青绿、头发紫色、暗部梅褐。人物与背景使用一致的像素颗粒、阶梯轮廓和成块明暗。暖光集中在灯、木桌和锅边，食材与脸保持清晰。
- **制作与验收**　每次生图或手绘都带同一原图。先在目标游戏镜头中合成站姿、坐姿、桌锅和运行中的餐带，与母图等比例并排检查，再拆为独立可摆放素材。菜单、气泡和角色卡沿用相同轮廓、色板及明暗处理。当前三维白模保留作历史原型。

## 2. 先交这一小组，不必一次做完整清单

先做“一个可复用的餐厅角落”，验证镜头、比例和画风：

1. 一块可平铺地板。
2. 一张双人桌：先一个横向视图，台面、桌腿和侧面完整。
3. 一把独立椅子：先一个视图，桌椅不要合成同一张图。
4. 一段横向直传送带、一段90度转角：带体与承载表面可分层。
5. 一个小火锅、一个空餐盘。
6. 一个角色正面静止小人：店长或员工露米任选其一。
7. 一张与该角色对应的二次元立绘，先一个常态表情。

这是9个设计项，角色身份和名字可调整。可附一张你排好的场景效果图，说明理想比例与风格；实际接入仍需要独立透明素材。

推荐先提交静态样板。代码接入后输出同一场景截图和可运行包，你确认视觉，再扩充方向、动作和其他角色。

## 3. 尺寸与比例：建议值，首批确认后再统一

当前游戏逻辑视口1280×800，原型格子40×40。这是代码原型的规格，不要求美术按40像素作画，也不要为了迁就原型把设计画小。

建议在1280×800画布上画一张场景效果图，先确定人物、桌椅和通道的相对大小。如果使用像素美术，选定一个原生像素尺度，后续用整数倍放大；场景接入时采用nearest采样。二次元立绘和UI使用独立的高清采样，不跟着场景像素化。

| 类型 | 建议首批源文件尺寸 | 注意 |
|---|---|---|
| 像素地板 | 32×32或64×64 | 二选一试样，不要混用两套像素密度；不是要求等距菱形地板 |
| 场景角色 | 64×96透明画布起步 | 可以更大或更小；所有动作保持同一画布和脚底位置 |
| 家具 | 按地板单元设计占地，画布包含物体高度 | 双人桌逻辑占地2×1；椅子独立占地1×1，不含在桌图里 |
| 火锅/餐盘/食材 | 与桌面比例一起试样 | 单独导出，场景食材可先用图标缩放验证，再补专用小图 |
| 物品/UI图标 | 128×128或256×256 | 透明背景，内容不要贴边；最终以缩小后辨识度为准 |
| 二次元立绘 | 高约1600—2400px，宽随姿势 | 透明底，不裁掉头发配饰；资料卡头像可由代码裁切复用 |
| UI参考稿 | 1280×800 | 标注边距与文本位置；不要把所有文字烘焙进一张背景 |

首批定稿时需要共同确认：格子视觉比例、人物显示高度、台面高度、描边、光照方向、像素密度。以上尚未成为强制规格。不要现在就批量画全部动作和旋转方向。

## 4. 2.5D拆分规则

### 家具与地面

- 地板可平铺；墙体和墙角单独导出，适应不同房型。
- 桌、椅、传送带、补餐点分别导出透明PNG，包含其可见侧面。
- 原型桌子带两个座位；正式美术桌和椅仍拆开，代码负责组合与后续独立摆放。
- 可旋转家具需要对应方向的视图，不能把斜俯视PNG直接平面旋转90度代替。横/竖视图先做；有明显朝向的椅子和柜体再补四向。
- 默认一件家具可以先交整张图。需要人物穿过拱门、走到柜台后等复杂遮挡时，才拆后层/前层，不强制所有素材分层。
- 落地阴影尽量另层或由代码生成，避免人物和家具高度调整时影子错位。材质自身的明暗可以画在素材里。

### 传送带

- 每个可连接单元需沿格子边缘无缝衔接。需要横直、竖直、四个转角；转角不等于把同一张图平面旋转。
- 底座/侧面与运动表面建议分开；也可先交整张静态样图，再由我确认如何拆。
- 食物、餐盘、箭头、分区色带不要画死在传送带里。餐盘和食物由代码移动，分区颜色、方向提示由代码处理。
- 如果设计包含滚动纹路，提供可重复平铺的表面纹理即可；不必手画整圈动画。

### 人物与锅具

- 人物脚底是定位基准；图中标记或文字注明脚底点坐标。不同动画帧画布不变，不逐帧裁边。
- 首批不要求转身动画；之后若需要侧面或背面，先补静态方向，再决定哪些动作值得画。
- 员工/顾客坐下时的姿势建议与站姿分开；桌面遮挡由代码完成。
- 锅体、汤面、食材分开更利于换锅底；首批可以先交锅体+汤面合成图，确认比例后拆。
- 蒸汽、发光、选中轮廓和悬浮气泡由代码完成；美术可给风格参考。

## 5. 动画制作建议

先静态后动画，帧数是建议，不是必须完成的数量。

| 动作 | 建议 | 第一轮是否需要 |
|---|---|---|
| 角色静止 | 1帧；后续2—4帧轻呼吸 | 需要1帧 |
| 行走 | 4—6帧，推荐约8fps试播 | 静态入场后再做 |
| 端盘 | 1个端盘站姿，后续复用/补行走 | 后续 |
| 顾客坐姿 | 1帧 | 第一组桌椅确认后 |
| 吃饭/操作 | 2—4帧 | 后续 |
| 立绘表情 | 常态、开心、困扰各1种 | 首批只常态 |

帧可交独立PNG，也可交sprite sheet。独立帧按idle_00.png、idle_01.png排序；图集须注明单帧尺寸、帧顺序、行列及fps。骨骼动画不作为首批要求。

## 6. 当前餐厅素材范围

完整可勾选表见同目录《餐厅美术清单.csv》。优先级：P0样板；P1完成餐厅；P2完善表现；后置内容不要与本批同时开工。

场景：地板、墙/角、门窗、桌椅、传送带、补餐点、厨房操作台、采购入口/摊位、营业铃、灯具、盆栽、餐具。

人物：店长、补餐员工露米、特殊客人莱恩、少量普通顾客。首批立绘只做一个角色；普通顾客不要求每人都画完整立绘。

食物：灯笼菇、霜角牛肉、跳跳虾、火椒、云绵豆腐、水晶萝卜、清炖霜牛；加空盘与锅具。

UI：公共面板、按钮及状态、菜品栏、气泡、采购、厨房、员工卡、特殊客人对话、日终账本、布局工具。界面文字、数量、进度条、状态切换由代码生成。

建议交付目录：source/存源文件，export/存PNG，preview/存整体效果图，notes.txt写版本和说明。源文件PSD、Aseprite、Krita等由设计师自行保留；接入只需导出图与必要参数。二次元插画与像素场景可以使用不同工具。

notes至少说明：角色或物体名称、原生尺寸、显示比例参考、脚底/落地点、动画帧率、哪些层需要遮挡人物，以及本次替换哪些文件。参数不知道可以留空，我从首批样板里适配。

我接到素材后的工作：校验透明度与尺寸 → 设置导入采样 → 接入节点/动画 → 调整视觉位置、Y排序、碰撞和点击区域 → 检查缩放、各方向与昼夜光照 → 输出游戏截图和试玩包。美术需求导致的代码适配由我完成。
